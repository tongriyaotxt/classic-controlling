# 传统算法的第一性原理分类框架

> 调研总纲：先回答「算法本质上消耗什么资源」，再据此判断「优化还能从哪里挤出来」。
> 本文件是三个子调研（控制算法 / CS 基础算法 / 优化算法）的统一分析框架。

## 1. 算法的第一性：五种根本资源

任何传统算法，剥到底层，消耗的不外乎以下五种资源。**优化的本质 = 在不改变语义的前提下，压低其中一种或多种资源的消耗**。

| # | 根本资源 | 典型算法族 | 复杂度度量 |
|---|---------|-----------|-----------|
| R1 | **比较/分支次数** | 排序、查找、选择、堆 | 比较次数下界 Ω(n log n) |
| R2 | **内存访问模式** | 哈希表、B树、图遍历、动态规划 | cache miss 次数、TLB miss |
| R3 | **浮点/整数运算量** | 矩阵乘、FFT、数值积分、求解器 | FLOPs、位运算次数 |
| R4 | **迭代收敛步数** | 优化迭代、不动点迭代、数值线性代数 | 收敛阶（线性/二次/超线性）|
| R5 | **信息获取成本** | 滤波估计、自适应控制、黑盒优化 | 采样效率、观测维度、信息利用度 |

## 2. 优化的六条第一性杠杆

对于任何一个开源实现，问这六个问题就能定位优化空间：

1. **L1 降复杂度**：算法本身是否还有更低的渐近界？（例：Strassen 之于朴素矩阵乘）
   - 大多数经典算法的渐近界已被钉死，空间很小，但常数项仍大有可为。
2. **L2 降常数（硬件利用）**：是否用满了现代硬件？SIMD（AVX2/AVX-512/NEON）、分支消除、cache 友好布局（SoA vs AoS）、预取、无锁结构。
   - **这是当前最大的一块洼地**：大量生产库仍停留在 2000 年代的标量教科书实现。
3. **L3 并行与并发**：多线程、GPU、分布式。 embarrassingly parallel 的部分是否还在串行跑？
4. **L4 问题结构利用**：稀疏性、对称性、带状、低秩、可分性、热启动（warm start）。
   - 求解器/控制器领域的主战场。
5. **L5 数值质量换速度**：混合精度（fp32/fp16 迭代精化）、容忍度自适应、近似计算。
6. **L6 自适应与免调参**：参数是否还靠人肉调？能否自动整定（auto-tuning）？

## 3. 三大领域的映射

### 3.1 经典控制算法
| 算法族 | 主要消耗的资源 | 首要优化杠杆 |
|--------|---------------|-------------|
| PID / 极点配置 | R3（每周期几次乘加） | L6 自动整定；L2 定点/MCU 优化 |
| LQR / LQG | R4（Riccati 方程求解） | L4 结构利用；L4 热启动 |
| Kalman/EKF/UKF | R3（每步矩阵分解/求逆） | L2 向量化；L5 平方根滤波换稳定性 |
| MPC | R4（每周期解一个 QP/NLP） | L4 热启动 + L3 嵌入式代码生成 |
| 滑模 / 反步 / ADRC | R3 | L2 实时性；L6 参数整定 |
| 模糊 / 自适应 | R5 | L6 规则/增益自学习 |

### 3.2 传统 CS 算法
| 算法族 | 主要消耗的资源 | 首要优化杠杆 |
|--------|---------------|-------------|
| 排序/选择 | R1 比较 + R2 移动 | L2 SIMD 分区/归并；L2 branchless |
| 哈希表/B树 | R2 cache miss | L2 紧凑布局、SIMD 指纹（SwissTable 路线）|
| 字符串匹配 | R1 + R3 | L2 SIMD 多模式匹配（Hyperscan 路线）|
| 图算法 | R2 不规则访存 | L3 并行；L2 CSR 压缩布局 |
| FFT/矩阵乘 | R3 FLOPs | L2 SIMD + L2 cache 分块（FFTW/BLIS 路线）|

### 3.3 经典优化算法
| 算法族 | 主要消耗的资源 | 首要优化杠杆 |
|--------|---------------|-------------|
| 单纯形/内点法 | R4 迭代 × 每次分解成本 | L4 稀疏分解；L3 GPU 内点 |
| QP（OSQP/qpOASES）| R4 | L4 热启动、代码生成 |
| NLP（IPOPT/NLopt）| R4 | L4 稀疏+自动微分；L3 并行线性代数 |
| 无导数（NM/CMA-ES/PSO/DE）| R5 函数评估次数 | L3 批量并行评估；L4 代理模型（surrogate）|
| 组合启发式（SA/禁忌/LNS）| R5 邻域评估 | L3 并行；L2 增量式目标更新 |
| L-BFGS/牛顿类 | R3 + R4 | L4 有限内存结构；L5 混合精度 |

## 4. 判断「值得优化」的优先级公式

```
优先级 ≈ 影响力（用户量 × 调用频率 × 性能敏感度）
       × 优化可行性（现有实现离最优的差距 ÷ 实现难度）
       × 生态位空缺（是否已有更好实现但没人迁移）
```

三个典型的高优先级画像：
- **教科书实现仍在生产服役**（例：某语言标准库或著名 Python 库是纯标量实现）→ L2/L3 收益大、难度低。
- **算法有公认更优变体但生态未迁移**（例：平方根 UKF、热启动 MPC）→ 生态位空缺。
- **被高频调用的基础原语**（排序、哈希、FFT、矩阵乘）→ 影响力杠杆最大。
